# 县域儿童青少年近视筛查复诊配镜补助平台

围绕**“筛查只是起点”**的理念，把学校年度视力筛查之后的告知、家长确认、医院复诊、处方、配镜、
补助、半年复查和学校日常干预（座位调整、户外活动、家长提醒、用眼指导）连成**一条完整的健康管理记录**，
并对请假、电话无法接通、导入错误、复诊差异大、自行外配眼镜、补助争议、配镜不适、复查未到场、
**家长拒绝复诊、连续拒绝且风险升高**等异常情形逐项登记、跟进到**闭环**，
供县教体部门与卫健部门核对**真实复诊率**与**干预执行情况**。

当家长以“**孩子只是疲劳用眼、休息就好**”为由拒绝到医院复诊时，平台**不会把拒绝简单标成“已处理”**，
而是把“拒绝原因、风险告知内容、确认时间、沟通人员”完整留痕，进入**拒诊跟进**链路：
健康老师在约定时间回访并登记座位/作业用眼/户外活动/家长当前态度（与前一次筛查同档比较）；
后续筛查继续下降时自动带出原拒诊记录与风险提示、重新生成复诊提醒；家长再次拒绝形成**新的跟进节点而不覆盖第一次**；
连续拒绝且风险持续升高时，学校可申请**班主任/社区医生共同沟通**，沟通结果与学校干预措施全部可追溯到该学生，
直到家长带孩子复诊才闭环。

技术栈：Vue 3 + Vite + Element Plus + Pinia + ECharts ｜ Spring Boot 3 + Spring Security/JPA ｜ PostgreSQL ｜ Redis（可选，本地自动降级为进程内缓存）。

## 一、一键启动（推荐：Docker Compose）

前置：安装 Docker / Docker Compose。

```bash
cd 176-feature-2-a
docker compose up -d --build
# 首次构建约 5-10 分钟；启动后访问
#   平台首页：   http://localhost:8080
#   Swagger UI： http://localhost:8080/swagger-ui.html
#   OpenAPI：    http://localhost:8080/v3/api-docs
```

Compose 会启动三个容器：`postgres:16`、`redis:7`、应用（8080，**前端已打进同一个镜像/端口**）。
应用首次启动自动建表并写入演示种子数据（3 片区、4 所学校、10 个角色账号、18 名覆盖各类场景的学生，
其中“许强”为拒诊全链路样例、“邓琳”为到期待回访样例）。

停止：`docker compose down`（保留数据）；`docker compose down -v`（同时清空数据卷）。

> 后端接口文档：全栈项目不强制要求 Swagger，本平台仍内置了 OpenAPI 3 文档与 Swagger UI 便于接口核对。

## 二、本地开发启动（无 Docker / 无外部依赖）

后端默认 `local` profile：使用 **H2 内存数据库**，Redis 自动降级为进程内缓存，零外部依赖。

```bash
# 后端（会自动加载前端构建产物；若仅做后端开发，见下方前端独立 dev server）
cd backend
mvn spring-boot:run                 # http://localhost:8080 （含内置前端与种子数据）

# 前端独立开发（热更新，自动把 /api 代理到 8080）
cd frontend
npm install
npm run dev                         # http://localhost:5173
```

如需指向外部 PostgreSQL/Redis：

```bash
java -jar backend/target/vision-platform.jar \
  --spring.profiles.active=postgres \
  --DB_HOST=localhost --DB_USER=vision --DB_PASSWORD=vision123
```

## 四、业务主流程（一个学生的健康管理链）

```
名单导入/既往档案
  └─ 现场筛查（裸眼视力、屈光度、散光、用眼习惯问卷、是否戴镜、复测建议、设备校准编号）
       └─ 学校健康老师复核（确认异常 / 误判排除 / 建议复测）
            └─ 家长告知（短信/电话/APP，电话不通自动累计并登记异常）
                 └─ 家长选择（县医院复诊 / 合作门诊复诊 / 暂缓并填原因）
                      └─ 医院复诊回写（真性近视、散瞳、处方参数、复查周期、补助初判、差异登记）
                           ├─ 配镜登记（合作机构 / 家长自行外配；配镜不适跟踪）
                           ├─ 配镜补助（申请 → 卫健核准 → 发放；争议进入复核）
                           ├─ 周期/半年复查（到期未到场自动催办并登记异常）
                           └─ 学校日常干预（座位调整、户外活动、家长提醒、用眼指导）
```

每一步都会写入该学生的**健康管理时间线**；各类异常情形自动进入**异常事项台账**，处理后闭环：

| 异常情形 | 触发点 | 闭环方式 |
|---|---|---|
| 筛查请假 | 筛查时勾选“请假未检” | 补检完成后闭环 |
| 家长电话无法接通 | 告知时勾选“本次未接通”（累计次数） | 家长接通并确认后闭环 |
| 批量导入信息错误 | 导入行电话格式错等（软错误不阻断） | 班主任修正信息后闭环 |
| 复诊与筛查差异较大 | 复诊勾选“差异大”并说明 | 卫健核对设备/结果后闭环 |
| 家长自行外配眼镜 | 配镜登记选“自行外配” | 凭证核验、补助核准时闭环 |
| 补助资格有争议 | 卫健标记 DISPUTE | 争议处理、补助发放后闭环 |
| 配镜后不适 | 配镜登记“不适” | 复诊调整后闭环 |
| 半年复查未到场 | 复查登记“未到场”（催办计数） | 学生补做复查后闭环 |
| 家长拒绝复诊 | 家长确认拒绝（记录原因/风险告知/确认时间/沟通人员） | **家长真正到院复诊后闭环，拒绝本身不允许标记“已处理”** |
| 连续拒绝且风险升高 | ≥2 次拒绝且后续筛查继续下降 | 班主任/社区医生共同沟通、家长复诊后闭环 |

### 家长拒绝复诊后的跟进链（本次新增）

```
家长拒绝复诊（拒绝原因/风险告知内容/确认时间/沟通人员 全部留痕；约定回访时间）
  └─ 健康老师在约定时间发起回访（座位、作业/近距离用眼、户外活动、家长当前态度）
        └─ 回访结果与前一次筛查放在同一档案比较（自动生成 视力/球镜 前后对比结论）
             └─ 后续筛查继续下降 → 自动带出“原拒诊记录 + 风险提示”，重新生成复诊提醒（RE_REMIND 节点）
                  ├─ 家长再次拒绝 → 生成新的 REFUSAL 节点（保留第一次，绝不覆盖）
                  └─ 连续拒绝且风险持续升高 → 学校申请班主任/社区医生共同沟通（JOINT_COMM 节点）
                        └─ 登记沟通结果 + 学校干预措施（同时写入学校干预台账，可追溯到学生）
                             └─ 家长带孩子到院复诊 → 整条拒诊跟进链路归档并闭环
```

设计要点：所有跟进均为**只追加（append-only）的节点表 `refusal_followup_node`**，节点类型为
拒绝/约定回访/复诊再提醒/多方共同沟通四类，每条带有序号、时间、沟通人和筛查快照；
学生档案新增“拒诊跟进”页签与“历次筛查结果”纵向对比表。

## 五、主要页面

- **监管看板**：筛查率、异常率、**真实复诊率（已复诊/筛查异常）**、异常闭环率、**拒诊跟进中/到期待回访**；各年级近视发展趋势、
  阶段漏斗、片区对比、各类异常事项（含家长拒诊、连续拒绝风险升高）分布、学校真实复诊率与干预执行数排名。
- **学生名单**：按学校/年级/片区/状态/关键字筛选；Excel(.xlsx)/CSV 批量导入（可下载模板）、导入错误修正、手工新增。
- **学生健康档案**：一条时间线串联筛查→告知→复诊→处方→配镜→补助→复查→干预→**拒诊跟进**，并分页签展示各类原始记录；
  页面内可直接执行业务操作（含记录拒诊、约定回访、共同沟通）。
- **现场筛查 / 复核与干预 / 家长告知确认 / 拒诊跟进 / 复诊处方 / 配镜与补助 / 复查随访 / 异常事项台账**：按角色显示菜单。
- **拒诊跟进**：三个页签——“拒诊跟进中”（拒绝次数、风险升高标记、最近节点、约定回访日期，可发起回访/记录再次拒绝/共同沟通）、
  “到期待回访”（按约定时间到期/逾期提醒，一键发起回访）、“共同沟通候选”（连续拒绝且筛查持续下降的学生，申请并登记班主任/社区医生沟通结果与学校措施）。
  学生健康档案内新增“拒诊跟进”页签，纵向展示拒绝→回访→再提醒→共同沟通全部节点，并附“历次筛查结果”对比表。

### 可手动复验的最小路径（拒诊跟进）
1. `docker compose up -d --build`（或本地 `mvn spring-boot:run`）→ 打开 http://localhost:8080
2. `screener` 登录 → 现场筛查 → 找“卫兰（待筛查）”录入异常视力（如双眼 4.8、球镜 -0.50）；
3. `doctor1` 登录 → 复核与干预 → 确认异常；
4. `teacher1` 登录 → 家长告知确认 → 记录告知 → 在“家长告知确认”或学生档案点**“记录拒诊”**，
   原因选“只是疲劳用眼”，填写风险告知并约定回访日期；
5. 左侧菜单进入**“拒诊跟进”** → “到期待回访”到期后点**“发起回访”**，填写座位/作业/户外/家长态度；
6. `screener` 对该生再录入一次更差的筛查（如双眼 4.5、球镜 -1.50）→ 档案中出现“复诊再提醒”并带出原拒诊记录；
7. 家长再次拒绝 → “记录再次拒绝”（档案中形成第 2 个拒绝节点，第 1 个保留）；
8. “共同沟通候选”里点**“申请/登记共同沟通”**，填写班主任/社区医生、沟通结果与学校干预措施；
9. `hospital` 复诊回写后，整条拒诊链自动闭环；`edu` 看板可看“拒诊跟进中/到期待回访”指标与异常事项分布。

### 拒诊跟进数据模型
- 表 `refusal_followup_node`（只追加）：`node_type` ∈ REFUSAL/RETURN_VISIT/RE_REMIND/JOINT_COMM，
  按 `seq` 构成每个学生的跟进节点链；拒绝原因（`RefusalReason`）、风险告知、确认时间、沟通人、
  回访四要素与家长态度（`ParentAttitude`）、下降对比与原拒诊节点外键、共同沟通参与方/结果/学校措施分列存储。
