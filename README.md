# 县域儿童青少年近视筛查复诊配镜补助平台

围绕**“筛查只是起点”**的理念，把学校年度视力筛查之后的告知、家长确认、医院复诊、处方、配镜、
补助、半年复查和学校日常干预（座位调整、户外活动、家长提醒、用眼指导）连成**一条完整的健康管理记录**，
并对请假、电话无法接通、导入错误、复诊差异大、自行外配眼镜、补助争议、配镜不适、复查未到场、
**家长认为“只是疲劳用眼”而拒绝复诊、连续拒诊风险升高**等异常情形逐项登记、跟进到**闭环**，
供县教体部门与卫健部门核对**真实复诊率**与**干预执行情况**。

家长拒绝复诊后，平台**不会把拒绝简单标成“已处理”**：每次拒绝都作为独立跟进节点，记录拒绝原因（归因+原话）、
风险告知内容、家长知情确认、确认时间与沟通人员；健康老师在约定时间发起回访，记录孩子座位、作业用眼、
户外活动与家长当前态度，并与历次筛查结果放在同一档案比较；后续筛查继续下降时自动带出原拒诊记录与风险提示、
重新生成复诊提醒（形成新节点，不覆盖历史）；家长连续拒绝且风险持续升高时，学校可申请班主任/社区医生共同沟通，
沟通结果与学校干预措施均可追溯到该学生。

技术栈：Vue 3 + Vite + Element Plus + Pinia + ECharts ｜ Spring Boot 3 + Spring Security/JPA ｜ PostgreSQL ｜ Redis（可选，本地自动降级为进程内缓存）。

## 一、一键启动（推荐：Docker Compose）

前置：安装 Docker / Docker Compose。

```bash
cd 176-b
docker compose up -d --build
# 首次构建约 5-10 分钟；启动后访问
#   平台首页：   http://localhost:8080
#   Swagger UI： http://localhost:8080/swagger-ui.html
#   OpenAPI：    http://localhost:8080/v3/api-docs
```

Compose 会启动三个容器：`postgres:16`、`redis:7`、应用（8080，**前端已打进同一个镜像/端口**）。
应用首次启动自动建表并写入演示种子数据（3 片区、4 所学校、10 个角色账号、16 名覆盖各类场景的学生）。

停止：`docker compose down`（保留数据）；`docker compose down -v`（同时清空数据卷）。

> 后端接口文档：全栈项目不强制要求 Swagger，本平台仍内置了 OpenAPI 3 文档与 Swagger UI 便于接口核对。

## 二、本地开发启动（无 Docker / 无外部依赖）

后端默认 `local` profile：使用 **H2 内存数据库**，Redis 自动降级为进程内缓存，零外部依赖。

```bash
# 后端（会自动加载前端构建产物；若仅做后端开发，见下方前端独立 dev server）
cd backend
mvn spring-boot:run                 # http://localhost:8080 （含内置前端与种子数据）

# 前端独立开发（热更新，自动把 /api 代理到 8080）
cd frontend
npm install
npm run dev                         # http://localhost:5173
```

如需指向外部 PostgreSQL/Redis：

```bash
java -jar backend/target/vision-platform.jar \
  --spring.profiles.active=postgres \
  --DB_HOST=localhost --DB_USER=vision --DB_PASSWORD=vision123
```

## 四、业务主流程（一个学生的健康管理链）

```
名单导入/既往档案
  └─ 现场筛查（裸眼视力、屈光度、散光、用眼习惯问卷、是否戴镜、复测建议、设备校准编号）
       └─ 学校健康老师复核（确认异常 / 误判排除 / 建议复测）
            └─ 家长告知（短信/电话/APP，电话不通自动累计并登记异常）
                 └─ 家长选择（县医院复诊 / 合作门诊复诊 / 暂缓并填原因）
                      ├─ 同意复诊 ─→ 医院复诊回写（真性近视、散瞳、处方参数、复查周期、补助初判、差异登记）
                      │                 ├─ 配镜登记（合作机构 / 家长自行外配；配镜不适跟踪）
                      │                 ├─ 配镜补助（申请 → 卫健核准 → 发放；争议进入复核）
                      │                 ├─ 周期/半年复查（到期未到场自动催办并登记异常）
                      │                 └─ 学校日常干预（座位调整、户外活动、家长提醒、用眼指导）
                      └─ 拒绝/暂缓（认为“只是疲劳用眼”等）
                            └─ 拒诊跟进节点①：记录拒绝原因+风险告知+家长知情确认+确认时间+沟通人员+约定回访
                                 └─ 健康老师约定时间回访（座位/作业用眼/户外活动/家长态度，与上次筛查同档比较）
                                      ├─ 家长同意复诊 ─→ 进入复诊链路，拒诊事项闭环
                                      └─ 仍拒绝 ─→ 新节点②（不覆盖①）；后续筛查继续下降自动重提醒（新节点）
                                           └─ 连续拒绝且风险升高 ─→ 申请班主任/社区医生共同沟通
                                                └─ 登记沟通结果+学校干预措施（均可追溯到学生）
```

每一步都会写入该学生的**健康管理时间线**；各类异常情形自动进入**异常事项台账**，处理后闭环：

| 异常情形 | 触发点 | 闭环方式 |
|---|---|---|
| 筛查请假 | 筛查时勾选“请假未检” | 补检完成后闭环 |
| 家长电话无法接通 | 告知时勾选“本次未接通”（累计次数） | 家长接通并确认后闭环 |
| 批量导入信息错误 | 导入行电话格式错等（软错误不阻断） | 班主任修正信息后闭环 |
| 复诊与筛查差异较大 | 复诊勾选“差异大”并说明 | 卫健核对设备/结果后闭环 |
| 家长自行外配眼镜 | 配镜登记选“自行外配” | 凭证核验、补助核准时闭环 |
| 补助资格有争议 | 卫健标记 DISPUTE | 争议处理、补助发放后闭环 |
| 配镜后不适 | 配镜登记“不适” | 复诊调整后闭环 |
| 半年复查未到场 | 复查登记“未到场”（催办计数） | 学生补做复查后闭环 |
| 家长拒绝复诊待跟进 | 家长选择暂缓/拒绝（记录原因、风险告知、沟通人员） | 回访/共同沟通后家长同意复诊才闭环；拒绝不标“已处理” |
| 连续拒诊需共同沟通 | 连续拒绝且后续筛查风险升高 | 班主任/社区医生共同沟通完成后闭环 |

## 五、主要页面

- **监管看板**：筛查率、异常率、**真实复诊率（已复诊/筛查异常）**、异常闭环率；各年级近视发展趋势、
  阶段漏斗、片区对比、异常事项分布（含拒诊待跟进、连续拒诊共同沟通）、学校真实复诊率与干预执行数排名；
  另设“**家长拒绝复诊持续跟进**”指标区：拒诊跟进中、再次拒绝人次、动员同意复诊（转化率）、共同沟通待办/完成。
- **学生名单**：按学校/年级/片区/状态/关键字筛选；Excel(.xlsx)/CSV 批量导入（可下载模板）、导入错误修正、手工新增。
- **学生健康档案**：一条时间线串联筛查→告知→拒诊→回访→复诊→处方→配镜→补助→复查→干预，并分页签展示各类原始记录；
  其中“**拒诊跟进**”页签把历次筛查结果与每个拒诊/回访/重提醒/共同沟通节点放在同一档案对照，
  再次拒绝形成新节点而不覆盖第一次；页面内可直接执行业务操作（含登记拒绝、健康回访、申请共同沟通）。
- **拒诊跟进与回访**（新增）：健康老师工作台，分“到约定回访时间 / 全部拒诊节点 / 多方共同沟通”三栏；
  在约定时间发起回访（座位、作业用眼、户外活动、家长态度），登记再次拒绝，或申请班主任/社区医生共同沟通并回填结果与学校措施。
- **现场筛查 / 复核与干预 / 家长告知确认 / 复诊处方 / 配镜与补助 / 复查随访 / 异常事项台账**：按角色显示菜单。

### 拒诊跟进数据模型（append-only，不覆盖历史）

- `refusal_followup`（RefusalFollowUp）：每个拒绝/回访/重提醒/共同沟通都是独立节点，`seq_no` 递增；
  存拒绝归因与原话、风险告知、家长知情确认、确认时间、沟通人员、约定回访日、回访四要素（座位/作业用眼/
  户外活动/家长态度）、比对的上次筛查视力、重新提醒内容并关联触发筛查记录。
- `joint_communication`（JointCommunication）：连续拒绝风险升高时申请班主任/社区医生共同沟通，
  记录申请/受理/结果与学校措施；学校措施同时落 `intervention` 表，全部可追溯到学生。
- 家长再次拒绝永远 `INSERT` 新节点；后续筛查下降由 `FlowService.submitScreen` 调
  `RefusalService.remindIfDroppedAfterRefusal` 自动带出原拒诊记录重提醒。
